# 设计：验证留档 + 管理员登录老板键（2026-09-22）

## 背景与目标

1. **验证留档**：现有「📍 验证我是否在工作区域」是纯查询、零记录（说明书明言"只做查询，不写任何排班数据"）。需要把每次验证落成持久流水，管理员可筛选查看并导出 CSV「物理留档」，证明大家确实到岗加班。
2. **管理员登录老板键**：登录页下拉框目前明示 `<option value="admin">管理员</option>`，所有人可见。需要默认隐藏该选项，登录页连按 6 下 `·` 才显示。

两项均为小功能，共用一次部署周期（本地提交 → push → 服务器 pull → systemctl restart）。

## 功能 A：验证留档

### A1. 记录时机与内容

- 触发点：现有 `GET /api/where-am-i`（登录会话或 `X-Check-Key` 调用）在完成 IP 判定后追加一条记录。
- **仅在管理员已配置工作区域 IP 段时记录**（未配置时验证无意义，保持现状不落库）。
- 字段（扁平结构，沿用 db.json 内其他集合的风格）：
  - `ts`（毫秒时间戳）
  - `name`（登录者姓名；`X-Check-Key` 自动化调用无身份，为空字符串）
  - `ip`（客户端真实 IP）
  - `inWorkArea`（布尔）
  - `matched`（命中的 IP 段，未命中为空串）
  - `source`（`web`=登录会话调用 / `api`=X-Check-Key 调用）

### A2. 存储

- `db.json` 新增顶层 `ipCheckLog` 数组，只追加。
- 封顶 10000 条，超出裁掉最旧（store.js 保存时顺带裁剪，与现有写库路径一致）。
- `data/` 整目录已 gitignore，流水永不入库。

### A3. 接口（沿用现有鉴权与错误风格）

| 接口 | 权限 | 行为 |
|---|---|---|
| `GET /api/ipcheck-log?month=YYYY-MM&name=某` | 管理员 | 返回流水（倒序），month/name 均可选，name 支持模糊忽略大小写；默认带最近 500 条，上限 2000 |
| `GET /api/ipcheck-log/mine` | 任一登录会话 | 返回本人最近 20 条（自动化来源无身份，不会出现） |
| `GET /api/ipcheck-log/export?month=YYYY-MM` | 管理员 | `text/csv` 下载；UTF-8 带 BOM（Excel 直接打开中文不乱码）；month 可省略=全部；文件名 `加班验证记录-YYYY-MM.csv` / `加班验证记录-全部.csv` |
| `GET /api/where-am-i` | 现有逻辑不变 | 附加：配置了 IP 段时追加记录；响应体新增 `recorded: true` 供前端提示 |

CSV 列：时间、姓名、IP、工作区域内、命中IP段、来源。

### A4. 页面

- **管理员·统计页**新增「📍 验证留档」卡片：月份下拉（含"全部"）+ 姓名筛选 + 记录表（时间/姓名/IP/是否区域内/命中段/来源）+ 「导出 CSV」按钮（带当前筛选月份）。
- **成员·排班页**：验证按钮结果提示改为"✅ 已留档：你在工作区域（IP x.x.x.x）"或"⚠️ 已留档：不在工作区域"；按钮下方新增本人最近验证记录折叠列表（默认收起，点开看最近 20 条）。
- 成员只能看到自己的记录；管理员表格中 `source=api` 的行显示来源"自动化"。

## 功能 B：管理员登录老板键

### B1. 行为

- `renderLogin()` 的下拉框**移除** `<option value="admin">管理员</option>`。
- 登录页全局 `keydown` 监听：连续 6 次按下「点键」计数，按其他键清零。
  - 认两种字符：`·`（U+00B7，中文输入法）与 `` ` ``（U+0060，英文输入法同一物理键），兼容输入法状态。
  - 计满 6 次 → 下拉框追加「管理员」选项并自动选中，保持到页面刷新；无任何提示文案。
- 管理员如何登录写进 `使用说明.md` 备忘（页面上不提示，否则失去隐藏意义）。

### B2. 决策：只藏 UI，服务端不动

真正的防线是管理员密码（登录已有按 IP 限速防爆破）。服务端按"是否按过老板键"来拒绝 admin 登录属于伪安全（状态在浏览器端，可伪造），且增加把管理员锁在门外的风险。故服务端 `/api/login` 保持不变。

## 部署流程（git 管理）

本地：`git add → commit → push origin`（SSH 别名 `github-workot` → GitHub `between-xtm/work_overtime`）。
服务器：`cd /root/work_overtime && git pull`，然后 `systemctl restart work-overtime`（juku 不涉及本次改动，不动）。
服务器工作区已验证干净、`data/` 忽略规则已验证，pull 无冲突风险。

## 边界与错误处理

- IP 段未配置：不记录，维持现状提示（`configured: false`）。
- 记录失败不阻塞验证响应本身（写库与响应同进程，正常不会失败；store.save 沿用现有原子写）。
- 流水裁剪仅发生在追加超限时，一次裁到 9000 条，避免每次保存都做裁剪。
- CSV 转义：姓名等字段按 CSV 标准转义（含逗号/引号/换行）。
- 时区展示沿用 `sch.nowDisplay(cfg.timezone)` 的现有口径；CSV 中时间格式 `YYYY-MM-DD HH:mm:ss`。

## 验收清单

1. 未配置 IP 段时点验证 → 不产生记录。
2. 配置后成员点验证 → db.json 出现记录、前端提示"已留档"、成员能看到自己的最近记录。
3. 自动化（X-Check-Key）调用 → 记录 source=api、name 为空。
4. 管理员统计页 → 筛选月份/姓名正确、导出的 CSV 在 Excel 打开中文正常、列齐全。
5. 普通成员调 `GET /api/ipcheck-log` → 403。
6. 登录页默认无「管理员」选项；连按 6 下 `·`（或 `）后出现；按其他键计数清零。
7. 重启服务后记录仍在；超过上限自动裁旧。
